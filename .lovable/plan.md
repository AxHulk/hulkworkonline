# План: английская версия сайта + переключатель языков

## Цель
Сделать сайт двуязычным (RU/EN) с возможностью переключения, сохранением выбора пользователя, корректным SEO и URL вида `/en/...` для английской версии.

## Этап 1. Технический фундамент (i18n)
1. Установить библиотеку `react-i18next` + `i18next` + `i18next-browser-languagedetector`.
2. Создать структуру переводов:
   ```text
   src/i18n/
     index.ts             // инициализация i18next
     locales/
       ru/common.json
       ru/home.json
       ru/services.json
       ru/blog.json
       ...
       en/common.json
       en/home.json
       ...
   ```
3. Подключить провайдер в `src/main.tsx`.
4. Настроить определение языка: URL-префикс `/en` → английский, иначе русский (по умолчанию).

## Этап 2. Маршрутизация
1. В `src/App.tsx` обернуть все маршруты так, чтобы поддерживался опциональный префикс `/en`:
   - `/` → RU, `/en` → EN
   - `/services/seo` → RU, `/en/services/seo` → EN
   - и т.д. для всех существующих маршрутов
2. Создать хук `useLocalizedPath()` для генерации ссылок с учётом текущего языка.
3. Заменить все `<Link to="/...">` на ссылки с локализованным путём.

## Этап 3. Переключатель языков
1. Компонент `LanguageSwitcher` (RU / EN) в `Header.tsx` (desktop + mobile меню).
2. При переключении: меняет URL (`/about` ⇄ `/en/about`), сохраняет выбор в `localStorage`.
3. Иконка-флаг или просто текст "RU | EN" в стиле дизайн-системы.

## Этап 4. Перевод контента (поэтапно по разделам)
Перевод выносится из JSX в JSON-файлы. Порядок по приоритету:

1. **Общие элементы** (`common.json`): Header, Footer, кнопки, формы, баннер cookie, согласие на ОПД, тосты.
2. **Главная** (`home.json`): Hero, Approach, Services, Portfolio, Blog, CTA.
3. **Страницы услуг**: Web Development, SEO, SMM, Behavioral Factors, ServiceCity.
4. **About, Portfolio, Contacts**.
5. **Legal-страницы**: Offer, Terms, Privacy, Unsubscribe (важно: для EN нужен отдельный текст, т.к. российские юр.требования к РФ-аудитории могут не применяться к EN — см. вопросы ниже).
6. **Blog**: интерфейс блога + статьи. 50 статей — самый объёмный блок (см. вопросы).
7. **Quiz-диалоги** и баннеры.
8. **404 / NotFound**.

## Этап 5. SEO для двух языков
1. В `SEO.tsx` добавить:
   - `<html lang="...">` управляется через `react-helmet-async`.
   - `hreflang` теги: `<link rel="alternate" hreflang="ru" href="..."/>`, `hreflang="en"`, `hreflang="x-default"`.
   - Локализованные `title`, `description`, `keywords` через i18n.
2. Обновить `sitemap.xml` — добавить EN-версии всех URL с hreflang-аннотациями.
3. Обновить `robots.txt` и `llms.txt` при необходимости.
4. JSON-LD (`buildBreadcrumbJsonLd`, Service, Organization) — локализовать названия.

## Этап 6. Бэкенд и формы
1. Edge-функции писем (`send-transactional-email`, шаблоны в `_shared/transactional-email-templates`) — добавить параметр `locale` и английские версии шаблонов писем (lead-notification и др.).
2. Логирование согласий (`logConsent`) — добавить поле `locale`.
3. Если в Supabase хранятся тексты (статьи блога, например) — добавить колонки `*_en` или таблицу переводов (нужно уточнить, см. вопросы).

## Этап 7. QA и публикация
1. Проверить все маршруты в обоих языках, переключение, обновление страницы (`.htaccess` уже настроен).
2. Проверить формы, отправку заявок, письма.
3. Проверить SEO-теги, hreflang, sitemap через валидаторы.
4. Прогнать Lighthouse для EN-версии.

## Технические детали
- **Библиотека:** `react-i18next` — стандарт для React, поддержка namespace, lazy-loading переводов, плюрализация, интерполяция.
- **Структура URL:** `/en/*` — самый SEO-дружественный вариант (лучше cookie/субдомена для индексации).
- **Fallback:** если ключ отсутствует в EN — показывать RU (или наоборот, в зависимости от приоритета).
- **Шрифты:** Montserrat / Inter поддерживают латиницу — менять не нужно.
- **Размер бандла:** переводы грузятся по namespace, можно настроить lazy-load по странице.
